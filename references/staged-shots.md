# Постановочные шоты — от бордоматика до отбора дублей

Результат для монтажёра — порядок планов, точная версия каждого выбранного файла, его исходный IN/OUT и место на таймлайне. Открытые планы остаются в том же списке. Карточку ниже можно вставить в чат, на борд или в существующий монтажный лист. JSON нужен только при использовании [локальной проверки](../scripts/takecheck.py).

## От сценария к бордоматику

1. Разбей сцену по изменениям, которые должен увидеть зритель. Для каждого плана зафиксируй крупность, действие и точку склейки. Например, зритель видит свободное гнездо, затем мастер вставляет кассету, затем загорается индикатор. Каждому из этих моментов назначь шот и источник — съёмку, игровой захват, генерацию или графику.
2. Разложи эскизы, ключи или стоп-кадры на шкале в монтажном fps. Проверь бордоматик с временным звуком, если склейка зависит от реплики, музыкальной доли или игрового события. Зафиксируй ревизию, порядок и длительности. Перенеси в лист все плановые позиции, включая пустые. Повторное использование футажа на другом стыке получает свой ID монтажной позиции и ссылку на тот же исходник.
3. На переходе запиши, куда смотрит и движется герой, где предмет, с какой стороны камера, какая фаза жеста покидает кадр. В игровом захвате проверь ещё и цепочку «ввод → событие → видимый отклик», состояние HUD и читаемость нужного сигнала. Для гибридного плана укажи, какой кадр съёмки или захвата задаёт перспективу, свет и положение для композитинга.

## Карточка плана и дублей

Скопируй один блок на монтажную позицию. Блок «Дубль» повторяй при каждой версии. Сохраняй промпт и привязки референсов именно той версии, с которой получили файл.

```text
Сцена / ID плана / позиция в бордоматике и ревизия:
Задача плана / крупность / вид источника:
Действие и наблюдаемый момент для склейки:
Герой, поза, взгляд и направление движения: IN → OUT
Камера, сторона оси, крупность и движение: IN → OUT
Реквизит, положение и состояние: IN → OUT
Цель в секундах / монтажный fps / таймлайн [IN,OUT) / нужные запасы:
Предыдущий план и его OUT / следующий и его IN / смысл стыков:
Референсы: роль → файл или ID → что именно фиксирует
Передача в AE: задача / plate и его ревизия / кадры / маска, трек или отдельный слой / ожидаемый результат:

Дубль: ID плана / версия / заменяет версию / что меняем и что сохраняем
Промпт для вставки (EN):
Настройки отдельно: канал, модель и версия, режим, привязка входов, поддержанные параметры
Решение: на просмотре | принят | архив | отклонён / причина / кто или какой документ подтвердил
Файл / при наличии ID задания или результата / fps источника / измеренные кадры:
Доступный диапазон источника [IN,OUT) / точка входа в монтаж / версия производной, если есть:
Свидетельство: файл проверки / выбранные кадры и номера / что просмотрено в движении
Осталось проверить / следующий адресный шаг:
```

**Пример постановки.** Сцена «Мастерская», план B02, борд v3. Предыдущий общий план показывает мастера слева у открытого прибора. B02 занимает кадры [24,72) при 24 fps, ровно 2 с. Камера сохраняет верхний ракурс. В начале кассета в правой руке над левым краем гнезда, в конце лежит заподлицо, пальцы разжаты. Склейка на загорание индикатора в B03. В AE передать чистую панель и задачу зажечь индикатор на первом кадре B03.

**Промпт B02, отдельным блоком для вставки**

```text
Locked overhead close-up. The technician's right hand slides the cassette from left to right into the open slot. Its front edge settles flush with the panel. The fingers release it and lift away. Hold the seated cassette for the cut.
```

**Настройки B02.** Исходное изображение — `bench-start.png`, роль «первый кадр», фиксирует руку, сторону гнезда и верхний ракурс. Режим — анимация от первого кадра. Запрошенный кадр 16:9. До выбора модели её версию, доступные длительности, параметры и стоимость оставить открытыми. Две секунды — потребность монтажа. Если у модели длиннее минимальный клип, в лист идёт фактически измеренный диапазон.

## Выбор режима и смена версии

| Что задано постановкой | Роль входа и решение |
|---|---|
| Свободный кадр по описанию | Text-to-video. Промпт задаёт предмет, действие, среду и камеру. |
| Утверждённая первая композиция | Start frame. Сохрани положение героя и реквизита, опиши движение от этого состояния. |
| Два утверждённых состояния одного действия | Start + end, когда версия модели принимает оба входа. Проверь совместимость ракурсов и физическую траекторию между ключами. |
| Нужно сохранить облик героя, предмета или среды | Назначь отдельные роли image/element references только в поддерживаемом режиме. Отметь, какие изображения фиксируют идентичность, а какие служат только ориентиром по стилю. |
| Есть эталон движения или игровой захват | Motion/video reference, если модель его принимает. Укажи интервал эталона, нужный ритм, переносимое движение и внешний вид, который должен сохраниться. |

Для будущего запуска возьми действующие каналы из `ae-motion-live/SKILL.md` §6 и `reference/generation-recipes.md`. В официальном Phygital+ MCP сверь модель через `list_models` и входы через `get_model_schema`. В официальном Higgsfield CLI проверь `higgsfield model get <job_type>` и оценку через `higgsfield generate cost` с параметрами задания. Длительность, aspect, resolution, seed, звук и negative prompt записывай только при поддержке конкретного режима. При недоступном входе оставь пометку о несовместимости, сохрани требуемую роль и согласуй изменение постановки. Перед расходом покажи модель, настройки, количество результатов, оценку за дубль и общую сумму. Если MCP не возвращает цену, укажи источник и дату оценки по прайсу. Получи явное согласие на расход. Сначала проверь действие на черновике. Повтору присвой следующую версию и запиши причину и согласованный расход.

## Отбор и передача

- Сверь реестр с плановыми позициями бордоматика. У выбранного дубля должны быть решение, версия, путь и доступные кадры. Несколько выбранных версий, дубль на просмотре или пустой слот остаются открытым решением. Архивный дубль сохраняет версию, промпт и причину замены. В адресе замены указывай, например, `B02/v02 заменяет B02/v01`.
- Покажи пять кадров в порядке монтажа — последний **использованный** кадр предыдущего плана, вход / ключевое действие / выход текущего и первый **использованный** кадр следующего. При неизвестной фазе действия обозначь средний кадр как выборку по времени. Номера исходных кадров, ID и версии оставь в подписях. При пропуске соседа отметь пустое место.
- Просмотри вход, действие и выход на скорости монтажа, затем обе склейки. Проверь позу, ось, направление, неизменность внешности и реквизита, момент контакта и реакцию. Привяжи замечание к версии и кадру. Например, «B02/v01, кадр 19 — рука разжимается до контакта; сохранить ракурс и исправить момент касания». При отсутствии просмотра запиши, какие свидетельства уже есть и что пока открыто.
- Монтажёру передай ревизию бордоматика, выбранные версии, локальные файлы, размещения и остаток запаса. Для AE приложи входную plate, нужный исходный отрезок, задачу и кадр приёмки. Если в монтаже стоит clean plate, сохрани связь «выбранный исходник → производная → позиции на таймлайне». При повторной правке укажи, какие позиции и задачи AE затронуты.

## Локальная проверка отбора

Таблицу клиента можно оставить в её формате. Для CLI собери небольшой JSON-срез из бордоматика и реестра версий. Для полной проверки включи в него все позиции бордоматика. Для проверки одного стыка достаточно фактической тройки из монтажного листа. `--shot` проверяет только названный план. Два соседних файла берутся из строк, примыкающих по времени. Для многослойных переходов и ретаймов передай согласованный CFR-плейаут или посмотри стык в монтажном экспорте.

```json
{
  "fps": 24,
  "shots": [
    {"scene":"Мастерская","shot":"B01","cut":[0,24],"takes":[]},
    {"scene":"Мастерская","shot":"B02","cut":[24,72],"takes":[
      {"version":"v01","status":"archive","file":"bench-v01.mp4"},
      {"version":"v02","status":"accepted","replaces":"v01","file":"bench-v02.mp4","use":[4,52]}
    ]},
    {"scene":"Мастерская","shot":"B03","cut":[72,96],"takes":[
      {"version":"v01","status":"review","file":"indicator-v01.mp4","use":[0,24]}
    ]}
  ]
}
```

В этом примере на B02 требуется 48 кадров. В источник входим с кадра 4, последним должен быть 51. Файл длиной 40 кадров после такой подрезки даст лишь 36. B01 остаётся незакрытым, B03 ожидает решения. Базовые поля для ручной работы можно хранить рядом в том же документе.

Запусти из корня `premiere-autopilot`. Для проверки нужен `ffprobe` в PATH. Для выдачи изображения нужны также `ffmpeg` и Pillow. Пути к медиа разрешаются относительно листа или могут быть абсолютными. Кадры отсчитываются с нуля, OUT исключается. `cut` относится к таймлайну, `use` — к исходнику. При длинном `use` укладывается отрезок от его IN длиной со слот, остаток доступен как хвостовой запас. Для дробного fps используй точную строку, например `"24000/1001"`.

```powershell
python scripts/takecheck.py sheet.json
python scripts/takecheck.py sheet.json --shot B02
python scripts/takecheck.py sheet.json --shot B02 --version v02 --action-frame 19 --frames B02-context.png
python scripts/tests/test_takecheck.py -v
```

Для `--frames` укажи свободное имя PNG или JPEG. `--action-frame` — номер кадра в исходнике внутри поставленного отрезка. Чтобы сравнить ещё спорный или архивный дубль, укажи его `--version`. Выдача кадров сохраняет статус отбора. Изображение показывает исходники без таймлайновых эффектов.

`accepted` — выбран, `archive` — сохранён прежний, `reject` — отклонён, `review` — требуется решение. Пустой `takes` оставляет план видимым. Код 0 подтверждает технический отбор в показанной области, 1 означает открытый отбор, проблему с медиа или выдачей кадров, 2 — ошибку входных данных. Проверь область отчёта перед передачей. Для каждого выбранного файла CLI декодирует первый видеопоток и сверяет кадры и их время с монтажной частотой. Скорость 1× и равный CFR — границы этой проверки. Художественное решение и задачи будущей генерации запиши в карточке отдельно.

# Сверка двух экспортов

Сравнивайте утверждённый экспорт с новой версией, когда нужно подтвердить границы правки, найти запоздавший титр или проверить, уехала ли фонограмма. Для работы нужны Python с NumPy, FFmpeg и FFprobe в PATH. Запускайте из корня Edit_Skill. Экспорты открываются только для чтения.

```powershell
python scripts/version_review.py master.mp4 revision.mp4 --out review-v02 --roi "title=80,810,1300,170" --allow-video 250:280
```

1. Укажите исходные файлы в порядке **до, после** и новую папку результата. Полный кадр проверяется всегда. Для субтитра, кнопки, таблички или игрового HUD добавьте одну или несколько областей `--roi "имя=x,y,ширина,высота"`. Координаты отсчитываются в пикселях от верхнего левого угла после применения поворота файла. Область можно перенести из `video_reference.py`. Прежняя запись `имя:x,y,ширина,высота` тоже поддерживается.
2. Перенесите из списка правок согласованные **временные** окна. У `--allow-video` и `--allow-audio` независимые списки. `--allow` разрешает изменения обеих дорожек. Каждый ключ можно повторить. В примере разрешено изменение картинки на кадрах 250–279. Звук проверяется и внутри этого интервала. Окно распространяется на всю картинку, поэтому из него также нужно просмотреть саму согласованную правку.
3. Откройте `review.html` в браузере с поддержкой кодека обоих файлов. Две версии воспроизводятся на общей шкале. Нажмите строку интервала для перехода к кадру с наибольшим различием. Кнопки ±1 переводят обе версии на соседний кадр, селектор звука переключает фонограммы. Счётчики показывают номера кадров обоих файлов и их время от начала экспорта. При наличии встроенного таймкода его стартовое значение подписано под плеером.
4. Сохраните `review.json` вместе с версией правок. Результат содержит параметры мастер-файлов, измерения полного кадра и каждой ROI, найденные интервалы звука, включения в согласованные окна и проблемные участки. Для переноса HTML на другую машину сохраните относительное расположение двух видеофайлов или повторите команду на месте.

## Общая шкала и якорь после перемонтажа

Кадры считаются с нуля. В JSON и параметрах интервал `[in, out)` включает начало, конец служит границей следующего кадра. В интерфейсе указаны первый и последний видимые кадры интервала. При разной длине инструмент проверяет общий участок и выносит оставшийся хвост на просмотр. Несовпадение отображаемых размеров, пропорций пикселя, нестандартный угол поворота или отличие кадровой сетки ограничивает автоматическую сверку. Для ручной сверки остаются два плеера.

Если удалили или вставили фрагмент, выберите один узнаваемый кадр в обеих версиях, например начало следующей реплики или первый кадр после склейки. Следующая команда сопоставляет 120 кадров, начиная со старого кадра 1050 и нового кадра 1100. На новой общей шкале они оба получают номер 0. При `--frames` заключение относится только к выбранному участку. Для нескольких вставок сверяйте участки между ними отдельно.

```powershell
python scripts/version_review.py master.mp4 revision.mp4 --out review-after-cut --align 1050:1100 --frames 120 --allow-audio 10:18
```

## Как читать измерения

### Фон, стекло и текст во время удержания

Если бриф меняет только часть кадра, отметьте интервалы чтения по раскадровке или режиссёрской разметке уже при первом запуске. Ключ `--hold` повторяется, конец интервала исключён. Нужен Pillow. Координаты объектов заранее не требуются.

```powershell
python scripts/version_review.py approved.mp4 candidate.mp4 --out review-holds --hold 150:181 --hold 510:541
```

В начале, середине и на последнем видимом кадре каждого удержания сравниваются одинаковые ячейки сетки 8×6. Откройте нужное удержание в HTML. Верхний ряд миниатюр показывает предыдущий экспорт, нижний — новый. По рисунку кадра выберите ячейку чистого фона, область изменённой панели и область хорошо видимых букв. В таблице есть отдельные значения для каждого участка, даже если среднее всего кадра ниже порога. R1C1 находится слева сверху.

- **Правка между версиями.** В поле `cross_mae` приведено изменение в каждой из точек по порядку. Превышение `--mae` вне разрешённого видеоокна отмечает соответствующий кадр удержания для просмотра. Номера кадров находятся в `hold_review.holds[].unexpected_frames`. Покадровая сверка всего экспорта и ранее заданных ROI по-прежнему работает независимо.
- **Живой фон на удержании.** Сравните `before_motion_mae` и `after_motion_mae` у ячейки фона. Каждое число — наибольшее различие между выбранными моментами внутри одного экспорта. Посмотрите направление и непрерывность движения в плеере. Полный цикл между точками может пропасть из выборки. Для такого движения передвиньте метку или добавьте точную ROI для покадровой сверки версий.
- **Чтение.** На тёмном фоне ориентиром для светлых букв служит пересечение масок по отношению к объединению (IoU). Отчёт даёт схожесть по удержанию в новой версии и отдельно между версиями по меткам. Пустая строка/тире означает меньше девяти подходящих пикселей. Светлые фильтры, отражения и иконки тоже попадают в маску. Проверьте начертание, позицию и контраст текста глазами в исходных кадрах. Для цветного или тёмного текста используйте визуальную сверку и при необходимости точную ROI. Пространственные измерения ведутся на изображении до 960 px по длинной стороне. Точный пиксельный допуск по мастер-файлу требует проверки в исходном разрешении.

### Картинка и звук по всей длительности

- **Картинка.** Полный кадр и каждый указанный прямоугольник отдельно уменьшаются до 96×64. По каждому кадру вычисляется среднее абсолютное различие RGB в шкале 0–255. Порог `--mae` по умолчанию равен 4. Небольшой титр может дать слабый сигнал по всему кадру и явное отличие в своей ROI. Внутри обнаруженного интервала инструмент ищет совпадение при временном сдвиге в пределах `--max-shift` кадров в обе стороны, по умолчанию 6. При однозначном совпадении `lag_frames: +2` означает, что в новой версии движение запаздывает на два кадра. Однокадровый скачок, существенно перерисованный план и повторяющееся движение могут дать интервал с `lag_frames: null`.
- **Звук.** Сравнивается первая звуковая дорожка файла, поканально, на частоте 8 кГц с учётом разницы стартовых меток аудио и картинки. В список интервалов попадает покадровый RMS разности выше `--audio-floor-db`, по умолчанию −42 dBFS. Задержка оценивается отдельно по сходству волны до семи раз за участок в пределах `--audio-search`, по умолчанию ±12 кадров. У положительного значения звук в новой версии позже, у отрицательного раньше. Например, +60 мс при 50 fps соответствуют +3 кадрам. Фонограммы с разными репликами, повторяющимся тоном или тишиной могут вернуть `no_unique_shared_signal`; наличие дорожек и отсутствие уверенного измерения указаны отдельно. Для изменений микса слушайте обе версии в полном качестве.
- **Статус.** Код выхода 0 означает, что на проверенном участке не найдено различий сверх заданных порогов вне согласованных окон. При отсутствии звука в обоих файлах JSON явно указывает `no_audio_in_either_export`. Код 1 означает, что отчёт сформирован и есть повод для просмотра, включая изменение геометрии, длины или состава звуковых каналов. Код 2 означает ошибку входов, параметров или записи. Для нового прогона укажите свежую папку.

Проверки CLI можно повторить командой `python scripts/tests/test_version_review.py -v`. Тесты создают временные локальные видео, включая исходник с матрицей поворота 90°, монтаж с обрезанным началом и пары с известным знаком задержки картинки и звука.

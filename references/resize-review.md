# Зависимые ресайзы анимации

После замены артборда, ассета или исходной композиции `scripts/resize_review.py` показывает, какие версии нужно пересобрать. Для каждой версии он сравнивает предыдущий и новый рендер на входе в изменённое состояние, в его опорном кадре, на выходе и в соседних опорных кадрах. Если несколько размеров входят в один ZIP, отчёт указывает пакет один раз и перечисляет затронутые размеры отдельно.

## Запуск

Из корня монтажного скилла запустите план или измерение. Для следующего прогона выберите новую папку.

```powershell
python scripts/resize_review.py family.json --changed "4751:10134" --plan-only --out qa/impact
python scripts/resize_review.py family.json --changed "4751:10134" --control desktop --out qa/frames
```

Откройте `review.html`. Клик по превью открывает PNG в полном размере. В `review.json` есть ID, имена пакетов, проверенные кадры, средняя абсолютная разница RGB, число изменившихся пикселей и их общий прямоугольник `[left, top, right, bottom)`. Для списка правок повторите `--changed`; для нескольких независимых контролей повторите `--control`.

## Семейство и тайминг

```json
{
  "formats": [
    {"key": "mobile", "ids": ["cover", "4751:10134", "cta"]},
    {"key": "wide", "ids": ["wide-cover", "wide-body", "wide-cta"]}
  ],
  "dependencies": {"4751:10134": ["product-panel"]},
  "timing": {"fps": 25, "holds": [10, 60, 110], "joins": [[20, 45], [75, 100]]},
  "outputs": [
    {"id": "phone", "format": "mobile", "deliverable": "campaign.zip", "size": [330, 960],
     "before": "v1/index.html", "after": "v2/index.html", "query": "render&fluid"},
    {"id": "desktop", "format": "wide", "deliverable": "campaign.zip", "size": [1060, 1400],
     "before": "v1/index.html", "after": "v2/index.html", "query": "render&fluid"}
  ]
}
```

- Вместо списка `formats` можно передать путь к проектному `formats.json` с полями `key` и упорядоченными `ids`. Используйте список реальных поставок и режимов просмотра в `outputs`. Отсутствие объявленного выхода у затронутой раскладки отмечается отдельно.
- `dependencies` необязателен. Ключ использует перечисленные справа источники. Вложенные связи тоже учитываются. Добавляйте их по составу слоёв, данным проекта или сборщику. Геометрическое сходство макетов само по себе не устанавливает связь. При наборе версий одного размера удобно использовать в ID название площадки или выпуска.
- Кадры нумеруются с нуля. `holds` — по одному кадру остановки на каждый артборд. `joins` — полуоткрытые диапазоны переходов между ними. `wrap` — необязательный последний переход из конечного состояния в первое, например `[747,775]`. Для другого темпа задайте свой `timing` у выхода. Дробную частоту задавайте точно, например `"30000/1001"`. Возьмите тайминг из утверждённого сториборда или монтажной шкалы.
- Укажите фактический размер выдачи. Для MP4 это размер декодированного изображения, для адаптивного HTML — viewport в CSS px при DPR 1. Каждый размер у точки переключения адаптивной вёрстки — отдельный выход. Если проект экспортирует имя активной раскладки, укажите его свойство, например `"layoutProperty": "N26C.key"`: обе версии должны выбрать заявленный `format`.
- Пути к исходным файлам отсчитываются от манифеста. Для HTML доступны локальные зависимости и seek-интерфейс `window.__motion` с `fps`, `duration` и `seek(t)`. Время проверяется по `time`, методу `time()` либо числу, возвращённому `seek(t)`. По умолчанию добавляется `?render`. Для адаптивной сборки укажите параметры её действительного просмотра. Достаточно локального Chrome и Python Playwright. Переменная `CHROME_PATH` позволяет выбрать установленный браузер. Для видео с постоянной частотой нужны FFmpeg и FFprobe. Обе ветки используют Pillow и NumPy.

## Как принять результат

На переходе выбираются его первый и последний кадры, а также три промежуточные фазы. Сравните, как изменились положение, маска и текст в опорном кадре и по обе стороны. Откройте PNG при размере доставки. Для версии без макета отдельно оцените поля, переносы и время чтения. Один неподвижный кадр или совпадение на нескольких отсчётах не проверяют всё движение. При правке темпа сверяйте соответствующие события и просматривайте переход целиком. Для покадровой проверки двух экспортов используйте [сравнение версий](version-review.md).

Код выхода 0 означает, что план построен или выборка снята без замечаний по установленным порогам. Код 1 означает, что отчёт готов и требует просмотра. Возможные причины — изменился контрольный выход, изменилось соседнее состояние, в выборке ожидаемая правка не видна или у зависимой раскладки отсутствует объявленный выход. Код 2 сообщает ошибку манифеста, рендера или чтения файлов. Разница канала должна превышать `--pixel-threshold` (по умолчанию 8 из 255); `--min-pixels` задаёт минимальную площадь для замечания (по умолчанию 1 пиксель). Выбирайте пороги по паре сопоставимых экспортов, особенно после перекодирования.

# Читаемость игрового события после кадрирования

Используйте `scripts/gameplay_review.py` для записи геймплея, когда нужно выбрать кадрирование под публикацию. Инструмент собирает короткие MP4 с исходным темпом и первой аудиодорожкой, кадры до действия, на входе и при результате, HTML и JSON. Работа идёт по локальному видео, видеоредактор и игровой движок можно закрыть.

1. Просмотрите запись. Выберите короткий диапазон и укажите, что видно перед действием, по чему его можно заметить и как зритель поймёт результат. Например, до рывка стоит отметка готовности, в начале меняются поза и статус, в конце персонаж оказывается у узнаваемого ориентира. Если кнопка физического ввода известна только из кода или лога, укажите источник в `context`. Если HUD скрыт и существенный отклик дан в окружении, отметьте именно этот отклик.
2. На каждом выбранном кадре обведите только то, что нужно зрителю для этой сцены. Дайте каждой области название и прямоугольник в пикселях. Для движущегося игрока координаты задаются отдельно на каждом кадре. Для текста можно указать минимальный приемлемый размер отмеченной области в финальном просмотре. Проверьте чтение глазами на целевом устройстве. Сохранённая рамка вокруг надписи сама по себе не подтверждает разборчивость букв.
3. Укажите кадрирования и размер, в котором зритель должен видеть ролик. Например, для вертикальной мобильной версии оценивайте 360 × 640. Для оценки при другом размере добавьте раскладку с тем же кропом и нужными размерами. Если центральный кроп теряет важную часть интерфейса, попробуйте сдвиг и перенос исходных пикселей интерфейса в свободную часть кадра через `inset`.
4. Запустите из корня монтажного скилла:

   ```powershell
   python scripts/gameplay_review.py path/to/event.json --out output/gameplay-review-v01
   ```

   Откройте `review.html` рядом с файлами отчёта, включите каждый ролик в обычном темпе и раскройте кадры, возле которых есть замечания. Кнопка под кадром переводит плеер на метку. Для вырезки из середины рядом показаны номер кадра и время по двум шкалам — исходной записи и короткого превью. Сверьте смысл и длительность реакции, ориентир, направление движения и показания HUD. Поле `reviewed` раскладки подходит для вывода монтажёра после просмотра именно этой версии. Обновление исходника или кадрирования требует нового просмотра.

## Манифест

```json
{
  "event": "Игрок открывает дверь",
  "source": "captures/door.mp4",
  "range": [30, 121],
  "beats": [
    {"phase":"before","frame":35,"observed":"Ручка двери и подсказка на месте.",
     "regions":[{"name":"Подсказка","box":[16,100,200,45],"minSize":[130,30]}]},
    {"phase":"action","frame":55,"observed":"Дверь начинает открываться.",
     "regions":[{"name":"Дверь","box":[515,250,170,300]}]},
    {"phase":"response","frame":95,"observed":"За открытой дверью виден проход.",
     "regions":[{"name":"Проход","box":[490,230,200,320]}]}
  ],
  "layouts": [
    {"name":"Горизонтальный","size":[1280,720],"crop":[0,0,1280,720]},
    {"name":"Вертикальный","size":[360,640],"crop":[438,0,405,720],
     "cropKeys":[[30,438,0],[55,420,0],[95,470,0]]},
    {"name":"Вертикальный с HUD","size":[360,640],"crop":[400,0,405,720],
     "inset":{"source":[16,96,220,54],"dest":[12,16,220,54]}}
  ],
  "edgeRegions":[{"name":"Фоновая панель статуса","box":[26,18,220,60],"range":[30,85]}]
}
```

- `source` — абсолютный путь или путь от манифеста. Кадры пронумерованы с нуля в порядке показа. `range` включает левую границу и исключает правую. Метки `before`, `action`, `response` идут в хронологическом порядке. В каждой фазе может быть несколько кадров. Время в отчёте отсчитывается от начала видео по декодированным PTS. Исходник может иметь переменную частоту. Инструмент сверяет PTS каждого выходного кадра с исходными с допуском 1 мс.
- `box` и `crop` имеют форму `[x,y,w,h]` относительно верхнего левого угла видимого растра с учётом display rotation. Поддерживается квадратный пиксель. `size` задаёт выходные размеры в пикселях. Стороны H.264 должны быть чётными. Кроп и результат имеют одинаковые пропорции, что сохраняет геометрию исходника.
- `cropKeys` задаёт движущееся окно постоянного размера. Каждый ключ содержит номер кадра оригинала и координаты левого верхнего угла. Первый ключ совпадает с началом диапазона и позицией `crop`. Координаты между ключами интерполируются с плавным разгоном и замедлением, после последнего ключа окно стоит. Эту траекторию используют и рендер, и замеры.
- `inset.source` — прямоугольник оригинала, `inset.dest` — прямоугольник в конечном кадре с теми же пропорциями. Разрешена одна статичная вставка из того же кадра. Перекрытая ею часть базовой картинки вычитается из видимой площади. Если один и тот же индикатор есть в двух местах, для сюжетной метки оценивается наиболее полный вариант.
- В необязательном `edgeRegions` укажите прямоугольники неподвижного HUD, титров или текста, которые допустимо оставить целиком либо полностью вывести из кадра. Укажите `range` по исходным кадрам, если элемент показывается только часть сцены. Без него берётся весь отрывок. Частичная видимость в основном изображении или вставке проверяется на каждом кадре активного диапазона. В `edgeAlerts` записываются интервалы [начало, конец). Целиком исчезнувший значимый сигнал контролируйте как область сюжетной метки. Для движущегося элемента используйте актуальные короткие диапазоны и проверку по видео.
- Откройте раздел «Края экспортированного кадра» в `review.html`. Переключайте левую, правую, верхнюю и нижнюю полосы при обычной скорости, откройте промежуточные кадры на полном размере. Лента включает начало, конец, сюжетные метки, ключи, середины промежутков, выборку по времени и кадры из каждого предупреждения. При движении окна ищите обрывки текста, появление панели из-за края, срезы фигуры и оружия. Геометрия зависит от разметки. Оцените в пикселях доставки, нужно ли поменять траекторию, сохранить интерфейс или подготовить чистую версию. После коррекции просмотрите итоговый MP4 повторно.
- Каждая область получает `clear` (целиком в кадре), `lost`, `clipped` или `small` (вся область в кадре, размер ниже `minSize`). `visible` — видимая доля площади, `mappedSize` — габариты пересечения области с кропом в пикселях доставки до вычитания перекрытия. При отсутствии `minSize` проверяется только геометрия. Эти измерения относятся к размеченным кадрам. Движение между ними смотрят в ролике. Понимание действия и прочтение HUD подтверждает монтажёр.
- При наличии звука берётся первая аудиодорожка в соответствующем диапазоне, кодек превью AAC. Для проверки микса откройте исходную дорожку. Выберите новую папку отчёта для каждого прогона. Код выхода 0 означает успешное построение всех вариантов, включая намеренно неудачный кроп. В `deliveries[].flagged` указано число замечаний к сюжету на метках, в `deliveries[].edgeAlerts` — интервалы частичной видимости дополнительно размеченных зон. Ненулевой код означает ошибку входов, валидации или рендера.

Для запуска нужны Python 3.10+, Pillow, NumPy и FFmpeg/FFprobe в PATH (проверено с FFmpeg 8). Локальный пример с записью движка, двумя вертикальными вариантами и проверенным результатом находится в `gen-out/gameplay-review-20261126/dash.json`. Для повторения укажите новую выходную папку.

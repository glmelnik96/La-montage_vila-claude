# Стыки сегментов и замыкание лупа

Из корня монтажного скилла запустите команду на готовом видео. Нужны FFmpeg, FFprobe, Python, NumPy и Pillow.

```powershell
python scripts/loop_review.py "screen.mp4" --out qa/loop-v3 --join 900 --join 1800 --expect-frames 2700 --expect-fps 30
```

Нулевой кадр начинает отсчёт. В `--join` указывайте первый кадр нового сегмента. Места заводской склейки лучше взять из монтажного листа или из расчёта рендера. Команда проверит каждую указанную границу и переход с последнего кадра на первый. Для одноразового вступления используйте `--once` и перечислите его внутренние склейки. Для дробной частоты передайте, например, `--expect-fps 30000/1001`.

**Что получает монтажёр.** Откройте `review.html`. На каждой границе видны четыре соседних кадра, кнопка воспроизведения и покадровый ползунок. У замыкания в одной последовательности идут хвост первого и начало следующего прохода. В него по умолчанию входят 12 кадров с каждой стороны. Увеличьте `--context 24`, если нужно оценить длинную паузу. В HTML встроены изображения и звуковой отрывок, подробности по каждому кадру есть в соседнем `review.json`. Просмотр через браузер показывает содержание, точность времени на физической LED-стене проверяется на её плеере.

**Замысел лупа.** Если автор явно предусмотрел два почти белых кадра на стыке, добавьте `--expect-flash 2`. Число означает суммарную длину вспышки, которая примыкает к стыку или пересекает его. Детектор проверяет белые кадры, яркостный контраст с соседями и выход в следующий план. Насыщенные цветные вспышки требуют отдельного просмотра. Для предусмотренной паузы `--expect-hold 4` задаёт суммарную длину одинакового состояния в кадрах до и после замыкания. Выберите контекст, захватывающий также движение до и после паузы. Оба флага относятся к замыканию. У внутренней склейки просмотрите отмеченную паузу в контексте номера.

**Что измеряется.** На прокси (длинная сторона 360 px, настройка `--proxy`) вычисляется средняя абсолютная разница RGB для всего кадра и для наиболее изменившейся из 16 областей сетки. Стык сравнивается с 90-м процентилем остальных шагов в выбранном окне. Большой шаг даёт кандидата на скачок. Совпадение соседних кадров внутри продолжающегося движения отмечается отдельно. Фоновая статика и очень медленное движение могут дать длинную область низкой активности. Для мелких деталей можно поднять `--proxy` до 1024. Согласованность направления движения, настроение перехода и видимость артефакта на стене оцениваются при просмотре.

Для первого аудиопотока команда читает исходную частоту и проверяет каждый канал. Разница граничных сэмплов сравнивается с соседними шагами в пределах 20 мс, дополнительно сравниваются локальные уровни RMS. На слух проверьте выделенный фрагмент, особенно на ударе или при смене тембра. Тишина в самом файле, отсутствие потока и неполное покрытие видео аудиосэмплами — разные случаи. Для мастера с несколькими программами звука подайте отдельный экспорт каждой программы.

**Точная адресация.** В обычных MP4/MOV с AVC, HEVC или ProRes проверяются число временных отметок и их соответствие числу видеосэмплов контейнера. В каждом запрошенном окне дополнительно сверяются фактические PTS декодированных кадров. При неподходящей индексной таблице команда получает полный список декодированных кадров через FFprobe. Такая проверка большого мастера касается выбранных стыков. При необходимости отдельной проверки декодируемости всего мастера выполните полный декод. Для CFR с округлёнными метками контейнера используются границы рациональной сетки, включая конец последнего кадра. У VFR интервалы воспроизведения берутся из фактических PTS, ожидание постоянной частоты даёт замечание.

Коды выхода: `0` — проверки прошли, `1` — отчёт готов и содержит кандидата на просмотр, `2` — измерение не выполнено. Для каждого прогона берите новую папку результата. Тесты создают тестовую дорожку со стереощелчком, видео с повтором кадра, холдом, белой вспышкой и переменными временными метками.

```powershell
python scripts/tests/test_loop_review.py -v
```

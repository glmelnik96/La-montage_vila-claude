# Профиль ритма и титров серии

Возьмите три или больше самостоятельных выпусков одной рубрики на сопоставимой стадии сдачи. Оставьте ещё один выпуск для проверки. Вертикальный ресайз, версия с правками и перекодировка того же выпуска дублируют наблюдение. Уточните, какие файлы утверждены клиентом и какие представляют внутренние сборки. Для короткого фрагмента повторяйте одну и ту же выборку, например первые 30 секунд, во всех выпусках.

```powershell
python scripts/series_profile.py learn train.json --out review/series
python scripts/series_profile.py check review/series/style.json episode04.json --out review/episode04
python scripts/series_profile.py measure episode04.json --out review/single
```

В `train.json` задайте название серии и массив `episodes` из трёх и более объектов по образцу ниже. Для `measure` и `check` нужен непосредственно один такой объект. Относительный путь к видео считается от манифеста. CLI принимает локальные экспорты, сохраняет SHA-256 и отвергает повтор исходника или ID при отложенной проверке.

```json
{
  "id": "ep04",
  "media": "episode04.mp4",
  "scope": [0, 75],
  "cutFrames": [30, 55],
  "cutEvidence": "Монтажные точки видимого видеотрека, сверены с экспортом.",
  "titles": [
    {"kind":"subtitle","in":5,"out":29,"text":"Почему меняется ритм?","box":[130,580,890,65],"speechFrame":8}
  ],
  "completeTitleKinds": ["subtitle"],
  "titleEvidence": "Строка прочитана в MP4. Появление и снятие проверены по соседним кадрам. Первое слово сверено по звуку.",
  "events": {"broll":{"frames":[30],"evidence":"Подтверждённый вход перебивки по монтажному листу и экспорту."}}
}
```

- **Монтаж.** Все номера кадров относятся к началу экспорта, `[in,out)` исключает последний номер. По умолчанию берётся весь файл, `scope` ограничивает измерение частью выпуска. Секунды вычисляются по фактическому времени показа кадров. `cutFrames` — первые кадры новых планов внутри диапазона. Если монтажный лист недоступен, уберите `cutFrames` и `cutEvidence`. Инструмент найдёт кандидатов в жёсткие склейки тем же методом, что [разбор референса](video-reference.md). Проверьте вспышки, смену интерфейса, наплывы и малоконтрастные стыки. Для применения другого порога задайте `--cut-threshold N` при обучении. При проверке используется сохранённый порог. Профиль разделяет подтверждённые монтажные точки и кандидатов.
- **Титры.** Возьмите текст и границы из дорожки титров, субтитров или разметьте по пикселям. Сверьте кириллицу, букву «ё» и отображение в конечном размере. Для вшитых субтитров с цветным акцентом используйте [проверку подсветки слова](caption-highlights.md). Роли, например `subtitle`, `question`, `lower_third` или `end_title`, анализируются отдельно. Для анимированной надписи зафиксируйте один критерий входа и выхода для всей серии — например полное раскрытие до начала исчезновения. Указывайте фактически видимый текст. Опциональный `box` измеряется в исходных пикселях как `[x,y,ширина,высота]` на характерном кадре. Записывайте единый способ измерения букв или плашки.
- **Речь.** В `speechFrame` можно указать подтверждённое начало соответствующего слова на той же шкале. Отрицательное значение `screen_minus_speech_s` означает, что текст появился раньше слова. Записывайте источник привязки, например ручное прослушивание или локальное распознавание с оценкой. Для немых заставок и вопросов на экране без дословного произнесения пропустите поле. Расшифровка сама по себе не подтверждает появление букв в кадре.
- **Полнота.** При выборочной разметке доступны длительности и число слов для отмеченных титров. Для расчёта доли времени укажите полностью размеченные категории в `completeTitleKinds`, либо `titlesComplete: true`, если просмотрели все разновидности. Тогда `titles: []` фиксирует проверенное отсутствие, а пропуск поля `titles` означает неизвестно. Перекрывающиеся интервалы одного вида входят в покрытие один раз.
- **Перебивки и звук.** По желанию передайте проверенные входы `broll`, музыкальные акценты `music_accent` или эффекты `sfx` в `events`. Каждый переданный перечень покрывает весь выбранный диапазон, содержит источник и номера первых кадров. Пустой перечень означает, что событий данного вида не найдено при просмотре. Если нет такого наблюдения, пропустите категорию. Этот CLI не классифицирует пики микса.

В `style.md` и `style.json` лежат частота склеек, длительность типичного плана, время первой склейки, а по каждому виду титров — длительность, число слов, положение, ширина, покрытие и привязка к речи при наличии данных. Один выпуск даёт одно значение для каждого показателя, затем по выпускам строятся минимум, медиана и максимум. JSON содержит исходные метки, измеренные параметры видео, способ разметки и число наблюдений. `comparison.md` показывает разброс эталонов рядом с отложенным выпуском. Для вывода по отдельному показателю нужны три независимых значения. Выход за диапазон требует редакторского решения с учётом содержания. Сохраните профиль до анализа отложенного выпуска.

Идея сопоставлять несколько роликов одного автора и отделять замер от наблюдения взята из [reverse-video](https://github.com/kelano86/reverse-video). Скрипт использует локальные FFmpeg, NumPy и Pillow из окружения монтажного скилла.

# Разбор плоского видеореференса

Когда монтажный проект недоступен, `video_reference.py` читает первый видеопоток файла и строит две разметки. Одна показывает кандидатов в жёсткие склейки. Другая показывает, когда меняется изображение внутри плана — во всём кадре или в областях, выбранных монтажёром. Например, непрерывный продуктовый ролик может содержать одно появление кнопки и несколько смен титров.

Из корня `premiere-autopilot`:

```powershell
python scripts/video_reference.py "D:/media/ref.mp4" --out "D:/review/ref"
python scripts/video_reference.py "D:/media/portrait.mp4" --out "D:/review/portrait" --roi "button=40,1470,1000,180" --roi "captions=50,1200,980,220" --at-frame 659
```

Откройте `report.html`. В нём перечислены кандидаты в склейки и кадры с обеих сторон. Блок каждого плана раскрывает интервалы изменения и низкой активности для отдельных областей. Превью изменений содержат кадр до начала измеренного диапазона, кадр с пиком изменения и последний кадр диапазона. Из отчёта доступна ссылка на `reference-<hash>.json`; этот же путь команда печатает в stdout. JSON с изменившимися данными публикуется под новым именем, затем атомарно обновляется HTML. Весь визуальный материал встроен в HTML.

## Кадры, время и области

- Нумерация декодированных кадров начинается с нуля. Все интервалы `[in, out)` используют исключённую правую границу. Граница склейки — первый кадр следующего предполагаемого плана.
- Время `t_in / t_out` в секундах отсчитывается от первого показанного кадра файла. `shot_t_in / shot_t_out` — от начала соответствующего плана. Для экспорта фрагмента прибавьте его известное положение в монтаже. Например, при старте экспорта в 20,04 с и границе в 3,48 с рассматриваем кадр секвенции на 23,52 с.
- Интервалы строятся по PTS декодированных кадров. JSON хранит среднюю fps дробью, длительность видеопотока, размер и признак совпадения PTS с равномерной сеткой в пределах одного тика. Для VFR при работе в секундах используйте PTS из интервалов.
- Область задаётся как `имя=x,y,ширина,высота` в пикселях декодированного изображения после поворота по метаданным (допускаются повороты, кратные 90°). При неквадратном пикселе координаты относятся к растру до коррекции пропорций пикселя. Области должны целиком лежать в кадре и иметь разные имена; `frame` зарезервировано для всего кадра.
- `--at-frame N` добавляет конкретный кадр со всеми выбранными областями. `--previews N` ограничивает количество автоматически выбранных примеров каждого вида. Все измеренные интервалы по-прежнему включаются в HTML и JSON.

## Как читать измерения

Анализ идёт по RGB-прокси с сохранением пропорций. Его длинная сторона по умолчанию 480 px; для мелкого текста можно передать `--proxy 960`. Метрика изменения — средняя абсолютная разница трёх каналов между соседними кадрами. По умолчанию активность начинается при двух уровнях из 255 (`--activity-threshold 2`). Первый кадр плана служит отдельной точкой отсчёта. Если на входе анимации движение нарастает постепенно, первое превышение порога может появиться позже первого авторского ключа.

Для склеек берётся разница всего кадра сверх медианного уровня соседних межкадровых изменений (до трёх с каждой стороны). Порог `--cut-threshold 10` задаётся в процентах полной RGB-шкалы. Вспышки и резкие перемещения камеры могут дать ложные кандидаты. Наплыв или склейка двух сходных кадров могут оказаться ниже порога. Постоянное движение задника, субтитры поверх интервью и компрессия влияют на измерения области. Просмотрите картинки на границе, затем исходник со звуком; название действия и монтажное назначение определяет редактор. Аудио, OCR и классификация происхождения шота в этот проход не входят.

Для одной и той же версии исходника, размера прокси и порогов результат воспроизводим. Имена шотов назначаются для данного разбора — изменение порога может изменить их нумерацию. Для связи с существующей секвенцией используйте версию источника и кадр/время.

Требуются FFmpeg и FFprobe в PATH, Python 3.10+, NumPy и Pillow. Прогоны выполняются локально. Тест включает ролик с двумя известными склейками, движение небольшой области, дробную частоту кадров, неравномерные PTS и ошибку координат.

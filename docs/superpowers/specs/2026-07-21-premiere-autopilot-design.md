# premiere-autopilot — дизайн скилла

**Дата:** 2026-07-21
**Статус:** утверждён (дизайн), готов к плану реализации
**Тип:** Claude Code skill (вариант A — Claude сам управляет живым Premiere)

## 1. Цель

Claude-скилл, который подключается к **живому Adobe Premiere Pro** и выполняет полный
цикл монтажа «под ключ» (turnkey), а также генерирует и вставляет AI-контент.
«Мозг» монтажа (что вырезать, что оставить, какие рилсы нарезать, какие главы) —
это Claude, а не встроенный в панель LLM.

**Эталонный сценарий (MVP):** подкаст/интервью (40–60 мин) →
- горизонтальная выжимка по смыслу (~5 мин) + главы;
- 3–5 вертикальных рилсов (30–60 сек);
- опциональные генеративные вставки (b-roll, обложки, закадровый голос).

## 2. Ключевой принцип

Скилл — **тонкий**. Вся тяжёлая логика уже существует в двух репозиториях
пользователя и **переиспользуется через локальные интерфейсы**, а не переписывается.
Скилл не редактирует исходники этих репозиториев.

Источники:
- `C:\Users\Глеб\Documents\Extensions-LLM-Chat_Pr` — CEP 12 расширение для Premiere.
- `C:\Users\Глеб\Documents\Phygital-Adobe-Studio` — FastAPI sidecar для AI-генераций.

## 3. Архитектура

```
        Claude Code (принимает решения)
                 │  Bash
     ┌───────────┴────────────┐
     ▼                        ▼
  pr.mjs                    gen.mjs
 (CDP :8098)             (HTTP :8765)
     │                        │
 CEP-панель LLM-Chat_Pr    Phygital sidecar
     │ PremiereBridge          │ /jobs → скачать файл
     ▼                        ▼
 ExtendScript → Premiere ◄── импорт готовых ассетов
```

### Два внешних сервиса-предпосылки

1. **Premiere + панель `LLM-Chat_Pr`** открыта, CEP-дебаг на порту `8098`.
   Канал в живую Premiere. **Поднимает пользователь** (Claude не спавнит Premiere).
2. **Phygital sidecar** на `127.0.0.1:8765`, авторизован (recon).
   Канал генераций. **Sidecar поднимает Claude**, но с оговоркой MSIX (см. ниже);
   **логин/recon — за пользователем**, разово. Дальше Claude ведёт цикл сам.

### Ограничение MSIX (Windows) и способ обхода — вариант B

Диагностика (2026-07-21) подтвердила: Claude Code на этой машине запущен в
MSIX-режиме (`%LOCALAPPDATA%\Packages\Claude_pzs8sxrjxfjjc`). Процессы,
спавнящиеся из агента через Bash, попадают в песочницу и видят
**виртуализированную** копию `%LOCALAPPDATA%\PhygitalStudio`, а не реальную —
т.е. не видят свежий `session.json`/`sidecar.token` от recon пользователя.

**Решение (вариант B): запуск sidecar вне контейнера через Windows Task
Scheduler (`schtasks`).** Запланированная задача стартует в реальной
пользовательской сессии → sidecar читает настоящий `session.json` и пишет в
реальный путь. Общение `gen.mjs` ↔ sidecar идёт по HTTP на `127.0.0.1:8765`
(сеть не виртуализируется), поэтому со стороны Claude проблем нет.

### Авторизация sidecar (точный контракт)

- Header: `X-Phygital-Sidecar-Token: <token>`; значение — содержимое
  `<app_data>/sidecar.token`.
- `/health` — публичный (без токена), используется для проверки живости.
- `gen.mjs` читает токен из `sidecar.token` и шлёт header на все запросы, кроме
  `/health`. При `401` — понятное сообщение (нужен recon / рассинхрон токена).

### Переиспользуется как есть (исходники не трогаем)

- `PremiereBridge` + `host/premiere.jsx` — операции с таймлайном.
- Транскрипция (`prepareTranscribeFromTimeline` + Whisper) — полная логика
  (чанкинг, загрузка в Cloud.ru) живёт в `timeline-transcribe.js` панели и не
  переписывается. **MVP:** пользователь разово запускает транскрипцию в панели
  (как recon), Claude читает результат из кэша
  `~/.extensions_llm_chat_pr/_llm_transcript_cache.json` (файл в корне профиля,
  вне MSIX-виртуализации AppData). `pr.mjs transcribe` возвращает кэш, если он
  свежий для активной секвенции, иначе просит пользователя нажать транскрипцию.
- Детерминированные пайплайны (паузы/паразиты/jump-cuts) — вызов через панель.
- Phygital `/jobs` API — генерации (image/video/voice/upscale).

## 4. Компоненты (пишем внутри папки скилла)

### `scripts/preflight.mjs` — проверка/подъём окружения
- Premiere-панель: коннект к CDP `8098`; если нет → инструкция открыть Premiere + панель.
- Sidecar: `GET /health`; если не отвечает → **Claude стартует sidecar вне
  MSIX-песочницы через `schtasks`** (создать задачу на `python -m app.main` с
  рабочей папкой `sidecar/`, запустить, дождаться `/health`).
- Авторизация: `/health` возвращает `jwt_ttl_sec`; если сессии нет/протухла →
  просит пользователя пройти recon (`python -m scripts.cli auth login`), ждёт,
  продолжает.

### `scripts/pr.mjs` — мост в Premiere (CDP-eval → `PremiereBridge.*`)
- `snapshot` — таймлайн (клипы, тайминги, fps)
- `transcribe` — запустить транскрипцию, вернуть путь к транскрипту из кэша
- `backup` — бэкап последовательности (чекпоинт)
- `cut --keep <intervals>` / `--remove <intervals>` — резы по таймкодам/транскрипту
- `pipeline <silences|fillers|jumpcuts>` — детерминированная чистка
- `markers <json>` — маркеры/главы
- `new-seq --vertical` — вертикальная последовательность под рилс
- `reframe` — авто-9:16
- `import <file>` / `overlay <file> --at <sec>` — вставка ассета

### `scripts/gen.mjs` — генерации (Phygital `/jobs`)
- `image --prompt` / `video --node <74|100> --prompt` / `voice --text` / `upscale --in <file>`
- внутри: create job → poll → download → вернуть локальный путь файла
- `--dry-run` — только `/jobs/preview-cost`, без запуска

### `SKILL.md` — оркестрация
Инструкция для Claude: как провести весь цикл D под эталонный сценарий,
модель одобрения B, чек-лист e2e.

## 5. Поток работы (модель одобрения B: полу-авто)

```
1. preflight            → оба сервиса живы + авторизация
2. pr backup            → один чекпоинт для отката
3. pr snapshot          → структура таймлайна
4. pr transcribe        → транскрипт (реюз Whisper)
5. [Claude думает]      → выбор highlight-сегментов (~5 мин)
6. pr cut --keep …      → горизонтальная выжимка
7. pr pipeline fillers/silences → чистка
8. [Claude думает] главы → pr markers …
9. [Claude думает] 3–5 моментов под рилсы →
   для каждого: pr new-seq --vertical + pr cut + pr reframe
10.[СТОП: подтверждение, тратит кредиты] gen video/image/voice →
   pr import/overlay (b-roll, обложки, закадр)
11. показ готового черновика: выжимка + N рилсов + куда встал генеративный контент
```

**Единственная точка обязательного подтверждения — шаг 10** (генерации стоят кредитов).
Остальное авто; откат — через бэкап с шага 2.

## 6. Обработка ошибок

- **Сервис недоступен** — `preflight` даёт конкретную причину и что включить;
  цикл не стартует, пока оба сервиса не готовы.
- **CDP-eval упал** (перезагрузка панели, cold-start) — `pr.mjs` ретраит по схеме
  из `bridge-premiere.js` (0/300/900 мс). Ошибки ExtendScript приходят структурно
  (`{_hostError, fn, msg, line}`) и показываются пользователю как есть.
- **Генерация зафейлилась/долгая** — `gen.mjs` поллит с таймаутом; при fail
  показывает ошибку и продолжает цикл без этого ассета (не блокирует весь монтаж).
- **Резы не сошлись** — интервалы валидируются до применения; при конфликте
  не применяем, показываем расхождение.

## 7. Безопасность / необратимость

- Бэкап последовательности — обязательный первый шаг любого мутирующего цикла.
  Откат: `activateSequenceById` на бэкап.
- Генерации (кредиты) — единственная точка обязательного подтверждения.
- Скилл не коммитит и не трогает исходники двух репозиториев — только читает и
  дёргает их интерфейсы.
- Секреты (API-ключи, сессии) не копируются в скилл — берутся из мест, где уже лежат.

## 8. Тестирование

- `preflight.mjs` — изолированный прогон (доступность без монтажа).
- `pr.mjs snapshot` — read-only smoke-тест живого моста.
- `gen.mjs --dry-run` — стоимость без запуска генерации.
- End-to-end — на реальном подкаст-проекте в Premiere по чек-листу в `SKILL.md`.
- Юнит-тесты хелперов в MVP не пишем (тонкие обёртки над уже протестированными
  сервисами); проверка — smoke + ручной e2e.
